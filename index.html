Architecture & design notes

Transaction flow

A newd pulse starts the master. Four beats use din multiplied by a count from zero to three, with TLAST asserted on the final beat. The top module connects the master directly to the slave; the FIFO is a separate module.

Packet buffering

The FIFO stores TDATA, TKEEP, and TLAST together. Its documented implementation prioritizes writes over reads and marks full at 15 occupied entries.

Current limitations

The README identifies missing upstream FIFO back-pressure, pointer wrap issues, and mutually exclusive reads and writes. The slave output is combinational, not a registered capture. This is a learning IP with documented improvement areas.

Key Takeaways

  • Back-pressure must propagate through the complete streaming path.
  • TLAST and byte-valid metadata must remain aligned with payload data.
  • Pointer wrap and simultaneous reads/writes need explicit boundary tests.

CDC approach & test scenarios

Pointer synchronization

Binary pointers address memory; Gray-coded pointers cross clock domains through two-stage synchronizers. This reduces metastability propagation risk; it does not eliminate metastability. Full and empty decisions use synchronized remote pointers.

Documented verification scope

The README describes reset, fill and drain, simultaneous read/write, random traffic, and pointer wraparound scenarios. Clock periods are simulation settings, not measured maximum operating frequencies.

Timing considerations

Remote pointer visibility and flag updates incur synchronization latency. Correct CDC implementation and physical timing constraints remain necessary.

Key Takeaways

  • Gray coding reduces multi-bit pointer-transition ambiguity.
  • Synchronizer latency affects full/empty flag visibility.
  • CDC architecture still requires appropriate physical timing constraints.

Timing Report

Design, inputs & timing constraints

Counter architecture

The counter cycles through 00, 01, 10, and 11. Its next-state equations are D0 = ~Q0 and D1 = Q0 ^ Q1. The netlist instantiates two DFFR cells, one INV, one XOR2, and three BUF cells, with asynchronous active-low reset.

PrimeTime flow

Load the example Liberty library and gate-level Verilog, link counter_2bit, back-annotate the SDF, and source the SDC. The Tcl script enables on-chip-variation analysis and clock reconvergence pessimism removal, then runs check_timing and generates setup, hold, clock, constraint, and design reports.

Timing model

The example library specifies nanosecond timing units, picofarad capacitance units, and a typical operating condition of 0.8 V at 25 degrees C. The SDF contains manually specified cell delays and flip-flop setup/hold checks. Both early and late operating conditions are shown as typical; enabling OCV mode alone does not demonstrate characterized multi-corner variation coverage.

Manual setup & hold calculations

Setup estimate: +1.57 ns

The handwritten analysis examines FF0 → XOR → BUF → FF1. The available budget is 2.00 - 0.10 = 1.90 ns after setup uncertainty. Clock-to-Q, XOR, buffer, and setup terms total 0.12 + 0.10 + 0.06 + 0.05 = 0.33 ns, giving 1.90 - 0.33 = +1.57 ns.

Hold estimate: +0.08 ns

The handwritten analysis examines the short feedback path FF0 → INV → FF0. It uses 0.11 + 0.04 = 0.15 ns for clock-to-Q and inverter delay. The hold requirement plus uncertainty is 0.02 + 0.05 = 0.07 ns, giving 0.15 - 0.07 = +0.08 ns.

These values are simplified hand calculations, not numerical worst-path slack reported by PrimeTime. They do not replace polarity-aware timing analysis with complete path and constraint coverage.

PrimeTime results & analysis scope

Recorded tool results

The shown run uses PrimeTime W-2024.09-SP5 on 14 March 2026. Both the maximum-delay and minimum-delay reports filter for slack below 0.00 ns and return no matching paths. The displayed constraint report lists no path-slack violators.

Evidence limits

The screenshots do not show numerical worst-path slack, timing-path details, or the output of check_timing. The SDC defines I/O delays, but the design report states that no pin input/output delays are specified. This discrepancy remains unresolved; complete constraint coverage cannot be established from the supplied material.

This is an educational STA exercise using an example library and manually specified SDF. The 500 MHz value is a clock constraint, not measured silicon performance or a demonstrated maximum operating frequency. The material does not establish production sign-off or independently verify the manual slack estimates.

Key Takeaways

  • Separate manual estimates from tool-reported worst-path slack.
  • No negative-slack paths does not establish complete constraint coverage.
  • Clock targets and analysis settings are not measured silicon performance.

Board bring-up and overlay loading

The board sequence uses a power cycle, UART monitoring, and XSDB target selection/programming. These steps describe the development setup, not a universal boot recipe: memory addresses, boot files, targets, and software versions depend on the actual platform.
